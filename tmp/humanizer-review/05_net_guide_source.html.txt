תוצר נדרש 
בסיום החניך יגדיר סימפטום והיקף, ישווה לייחוס, יתקדם לפי שכבות, וישנה משתנה אחד תוך אימות ותיעוד.

להזכיר שהעברת תקלה טובה כוללת ראיות, שעה והיקף.

שינוי, רק בסוף 
השינוי מגיע רק לאחר שיש שאלה וראיה, לא בתחילת האירוע, ותמיד אחד בלבד. לאחר מכן: בדיקה חוזרת מול אותו קריטריון, ואז תיעוד והעברה. 
איך להעביר 
הפוך כל תלונה למשפט שניתן להפריך: ״תחנה A אינה פותחת server.unit בפורט 443 מאז 10:15; תחנה B כן״. 02 · היקף וייחוס 
הפער מול מערכת תקינה מקצר את רשימת החשודים 
היקף 
תחנה אחת, VLAN או מקטע, שירות אחד, או אתר שלם. כל היקף מכוון לחשודים אחרים. 
ייחוס 
משווים מתאם, כתובת, Prefix, Gateway, DNS, Route ותוצאה לאותה מערכת תקינה או לתכנון. 
ipconfig /all IPv4 Address 10.20.30.15 Default Gateway 10.20.30.1 DNS Servers 10.20.10.10 
כל שדה מקבל משמעות רק מול תכנון או ייחוס תקין 
המספר החשוב הוא הפער, לא עצם הופעתו בפלט. 
זהירות 
אין להעתיק הגדרה מתחנה אחרת בלי לוודא שהיא אמורה להיות זהה. 03 · Link ו-VLAN 
הפיזי קודם, אך Link תקין אינו סוף הבדיקה 
אין Link: בדוק כבל, מחבר, הזנה, מתאם ופורט. יש Link אך אין שכנות צפויה: אסוף MAC, כתובת, פורט ושעה והעבר לבדיקת VLAN. 
VLAN תחנות 
VLAN 10 A, B 
VLAN 20 C, D 
Link תקין אינו מוכיח מעבר בין רשתות 
המתג מחבר את שתי הרשתות ברמה הפיזית, ולכן Link יכול להיות תקין משני הצדדים. מעבר תעבורה בפועל בין VLAN 10 ל-VLAN 20 דורש ניתוב; בלעדיו התקשורת נעצרת בגבול הזה. מדדי הקישור הבודד (Throughput) יכולים להיראות תקינים, בעוד המעבר בפועל בין הרשתות (Goodput) חסום כל עוד אין ניתוב. 
הטכנאי אינו משנה VLAN, הוא מוכיח את הגבול שבו התקשורת מפסיקה. 
ראיה טובה להסלמה 
Link Up, פורט פיזי מזוהה, כתובת ומסכה תואמות, אין ARP ל-Gateway, מערכת ייחוס באותו מקטע עובדת. 04 · כתובת, שכן ודרך 
IP, ARP וניתוב נבדקים בסדר הזה 
כתובת או Prefix שגויים משנים את ההחלטה מקומי/מרוחק. ARP חסר ל-Gateway מצביע על בעיה לפני הניתוב. Route שגוי מפנה תעבורה לכיוון אחר. 
תחנה 
IP יעד. שולחת ARP ל-MAC של השער. 
נתב 
טבלת ניתוב. בונה מסגרת Ethernet חדשה להמשך הדרך. 
שרת 
IP יעד, הכתובת הסופית של המסלול. 
כתובות IP נשארות מקצה לקצה; כתובות MAC מתחלפות בכל קישור. 
הפרד בין ״אין שכן״ לבין ״יש שכן אך אין דרך״. 
1 השווה כתובת, Prefix, Gateway ו-DNS מול תכנון. 
2 צור תעבורה ואז בדוק ARP; השווה MAC לציפייה. 
3 בדוק את הנתיב הספציפי שנבחר, לא רק Default Gateway. 05 · שירות, זהות וסגירה 
מפרידים DNS מפורט, ואז בודקים זמן ואמון 
גישה לפי IP מול שם מבודדת DNS. פתיחת TCP מול Ping מבודדת שירות. ב-Domain בודקים DNS, זמן, איתור DC, כרטיס ותעודה (Kerberos) לפני סיסמה. Domain זהות ואמון DNS / Service שם ופורט IP / Route כתובת ודרך Ethernet VLAN ושכנות Link כבל ומתאם 
עוצרים בשלב הראשון שבו הראיה אינה תואמת לציפייה. 
התהליך עובר מהחוליה הפשוטה והקרובה אל התלות הגבוהה יותר. 
סגירת תקלה 
שנה דבר אחד, חזור על אותה בדיקה, השווה לייחוס, ותעד סימפטום, היקף, שעה, ראיות, שינוי ותוצאה. 
תקלה לסירוגין 
אסוף מדדים לאורך זמן וקשר אותם לשעה ולאירועים; מדידה יחידה יכולה לפספס קפיצות Loss או Latency. סיום · מפת העברה
