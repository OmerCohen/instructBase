מטרת השיעור

להפוך את המושגים והכלים לתהליך עקבי שמבודד את החוליה הראשונה שאינה תואמת לציפייה.

בסוף השיעור

מתלונה כמו ״הרשת לא עובדת״ החניך מגיע לסימפטום והיקף מוגדרים, משווה לייחוס ומתקדם לפי שכבות. כשהוא מתקן, הוא משנה דבר אחד, בודק שוב ומתעד.

הכנה מראש

  • בחרו תרחיש תקלה מוכר אחד ללוות את כל ההסבר.
  • הכינו תכנון או ייחוס תקין סכמטי להשוואה.
  • הזכירו שהעברת תקלה טובה כוללת ראיות, שעה והיקף.

היקף השיעור

השיעור עוסק בבידוד התקלה ובהעברתה עם ראיות לגורם שמוסמך לשנות VLAN, שרתים או מדיניות. אין בו פרק תרגול: כל תקלה שמוצגת ממחישה שלב אחד בתהליך.

01 · הגדרת הבעיה

מגדירים סימפטום, היקף וציפייה לפני שנוגעים במערכת

״לא עובד״ אינו תיאור. צריך לדעת מה הפעולה, מה התוצאה, מתי התחיל, מי עוד מושפע, ומה היה אמור לקרות.

מתי משנים

רק אחרי שיש שאלה וראיה, ורק דבר אחד בכל פעם. אחר כך חוזרים על הבדיקה מול אותו קריטריון, מתעדים ומעבירים.

איך להעביר

נסחו כל תלונה כמשפט שאפשר לבדוק: ״תחנה A אינה פותחת server.unit בפורט 443 מאז 10:15; תחנה B כן״.

02 · היקף וייחוס

הפער מול מערכת תקינה מקצר את רשימת החשודים

היקף

תחנה אחת, VLAN או מקטע, שירות אחד, או אתר שלם. כל היקף מכוון לחשודים אחרים.

ייחוס

משווים מתאם, כתובת, Prefix, Gateway, DNS, Route ותוצאה לאותה מערכת תקינה או לתכנון.

ipconfig /all

IPv4 Address10.20.30.15
Default Gateway10.20.30.1
DNS Servers10.20.10.10

כל שדה מקבל משמעות רק מול תכנון או ייחוס תקין

זהירות

אין להעתיק הגדרה מתחנה אחרת בלי לוודא שהיא אמורה להיות זהה.

03 · Link ו-VLAN

קודם החיבור הפיזי, אחר כך השכנות המקומית

כשאין Link בודקים כבל, מחבר, הזנה, מתאם ופורט. כשיש Link אבל אין שכנות צפויה, אוספים MAC, כתובת, פורט ושעה ומעבירים לבדיקת VLAN.

VLANתחנות
VLAN 10A, B
VLAN 20C, D

Link תקין אינו מוכיח מעבר בין רשתות

המתג מחבר את שתי הרשתות ברמה הפיזית, ולכן Link יכול להיות תקין משני הצדדים. מעבר תעבורה בפועל בין VLAN 10 ל-VLAN 20 דורש ניתוב; בלעדיו התקשורת נעצרת בגבול הזה.

הטכנאי לא משנה VLAN. תפקידו להראות באיזה גבול התקשורת נעצרת.

ראיה טובה להסלמה

Link Up, פורט פיזי מזוהה, כתובת ומסכה תואמות, אין ARP ל-Gateway, מערכת ייחוס באותו מקטע עובדת.

04 · כתובת, שכן ודרך

IP, ARP וניתוב נבדקים בסדר הזה

כתובת או Prefix שגויים משנים את ההחלטה מקומי/מרוחק. ARP חסר ל-Gateway מצביע על בעיה לפני הניתוב. Route שגוי מפנה תעבורה לכיוון אחר.

רכיבמה קורה בו
תחנהיודעת את IP היעד ושולחת ARP כדי לקבל את ה-MAC של השער.
נתבבוחר דרך לפי טבלת הניתוב ובונה מסגרת Ethernet חדשה להמשך הדרך.
שרתIP היעד, הכתובת הסופית של המסלול.

כתובות IP נשארות מקצה לקצה; כתובות MAC מתחלפות בכל קישור.

מפרידים בין ״אין שכן״ לבין ״יש שכן אבל אין דרך״.

1משווים כתובת, Prefix, Gateway ו-DNS לתכנון.
2יוצרים תעבורה, בודקים ARP ומשווים את ה-MAC לצפוי.
3בודקים את הנתיב הספציפי שנבחר, ולא רק את ה-Default Gateway.
05 · שירות, זהות וסגירה

מפרידים DNS מפורט, ואז בודקים זמן ואמון

גישה לפי IP מול שם מבודדת DNS. פתיחת TCP מול Ping מבודדת שירות. ב-Domain בודקים DNS, זמן, איתור DC, כרטיס ותעודה (Kerberos) לפני סיסמה.

עוברים מהחוליה הקרובה והפשוטה אל התלויות שמעליה, ועוצרים בשלב הראשון שבו הראיה אינה תואמת לציפייה.

סגירת תקלה

משנים דבר אחד, חוזרים על אותה בדיקה ומשווים לייחוס. בתיעוד: סימפטום, היקף, שעה, ראיות, שינוי ותוצאה.

תקלה לסירוגין

אוספים מדדים לאורך זמן ומקשרים אותם לשעה ולאירועים. מדידה יחידה יכולה לפספס קפיצות Loss או Latency.

שאלת סיום

איזו ראיה קצרה ביותר תבודד את השלב התקול בתרחיש שהצגת, ומה תתעד להעברה?

טעות נפוצה

טכנאי מחליף כבל, משנה DNS ומאתחל את התחנה בבת אחת. הקשר חוזר, אבל אי אפשר לדעת מה פתר את התקלה, והיא נסגרת בלי בדיקה חוזרת מול אותו קריטריון.
