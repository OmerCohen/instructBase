מטרת השיעור

ללמד בחירת כלי לפי השאלה הפתוחה, והפקת ראיה מדויקת מהפלט.

תוצר השיעור

החניך בוחר את הכלי שמתאים לשאלת האבחון וקורא בפלט את השדה שעונה עליה.

הכנה מראש

  • ודאו שהפקודות זמינות בגרסת Windows המקומית.
  • הכירו את חלופת ה-GUI לכל PowerShell cmdlet שחסר.
  • השתמשו בכתובות ובשמות לדוגמה, בלי נתונים רגישים.

היקף השיעור

עובדים רק בכלים המובנים ב-Windows, ומכל פלט קוראים את השדה שעונה על השאלה. הגדרות מערכת לא משנים בשיעור.

שאלה לפתיחה

איזו פקודה עונה על השאלה "האם Windows רואה Link"?

01 · בחירת כלי

איזה כלי עונה על איזו שאלה

Linkכתובתשכןמסלולשם ופורטזהות
Get-NetAdapter ipconfig /all arp -a route / tracert DNS / Test-NetConnection w32tm / nltest / klist

אין צורך להריץ את כל הפקודות בכל אירוע. מריצים רק את הכלי שעונה על השאלה הפתוחה ומשווים את התוצאה לצפוי.

איך להעביר

עברו על הטבלה עמודה אחר עמודה, ובכל עמודה בקשו מהחניכים לנסח את השאלה שהכלי עונה עליה.

02 · זהות מקומית

Get-NetAdapter ו-ipconfig מראים מה Windows רואה

Get-NetAdapter מציג מתאם, Status, קצב קישור ו-MAC. ipconfig /all מציג כתובת, מסכה, Gateway, DNS ומצב DHCP.

פלט לדוגמה: ipconfig /all

שדהערך לדוגמה
IPv4 Address10.20.30.15
Default Gateway10.20.30.1
DNS Servers10.20.10.10

משווים כל שדה לתכנון או למערכת ייחוס תקינה. בסביבה סטטית הערכים צריכים להתאים לתכנון, ולא מספיק שייראו סבירים.

זהירות

Status Up אינו מוכיח VLAN, IP או דרך.

בודקים את המתאם הפעיל הנכון; מתאמים וירטואליים יכולים להטעות.

03 · שכנות ומסלול

Ping, ARP, route ו-tracert עונים על שאלות שונות

כלימה הוא מראה
Pingתגובת ICMP ו-RTT.
arp -aמיפוי IP מקומי ל-MAC, לאחר שהייתה תעבורה.
route printאת החלטת הניתוב של התחנה.
tracertמי השיב לאורך הדרך. תלוי בתגובות ציוד ביניים; כוכבית או חוסר תגובה אינם בהכרח הפסקת העברת תעבורה.
תחנהנתבשרת
IP יעדטבלת ניתובIP יעד

בדרך: ARP מאתר את ה-MAC של השער, ובכל קפיצה נבנית מסגרת Ethernet חדשה.

שימו לב

רשומת ARP חסרה לבדה אינה תקלה; ייתכן שעדיין לא נשלחה תעבורה ליעד.

04 · שם ופורט

Resolve-DnsName ו-Test-NetConnection מפרידים שם משירות

ב-DNS מחפשים מי ענה, איזה שם נשאל, סוג רשומה והכתובת שהוחזרה. בבדיקת פורט מחפשים כתובת מרוחקת, פורט ותוצאת TCP.

תחנהDNSשרת
server.unitשם ← כתובת10.20.40.25

כשהמשתמש פונה בשם, בודקים קודם את פתרון השם, ורק אחר כך את השירות בכתובת שהוחזרה.

מה לא הוכח

TcpTestSucceeded=True מוכיח שנפתח TCP ליעד ולפורט; הוא אינו מוכיח שהיישום החזיר תוכן תקין.

05 · Domain, תעודה ואירועים

בדיקות Kerberos, תעודה ואירועים

w32tm /query /status בודק זמן ומקור; nltest /dsgetdc:domain בודק איתור DC; klist מציג כרטיסי Kerberos. תעודה ואירועים נותנים שם, תוקף, מנפיק ורצף בזמן.

DNSזמןKerberosהרשאה
איתור DCתוקף כרטיסאימותקבוצות

תעודה

את התעודה פותחים ב-Certificate Viewer ובודקים שם, תוקף, מנפיק ושרשרת.

ב-Event Viewer מתעדים שעה, מקור, Event ID והודעה מלאה.

חלופה

אם כלי PowerShell אינו קיים בגרסה המקומית, משתמשים בחלון המקביל; השאלה והשדה לא משתנים.

מילון קצר למדריך

Status Up: המתאם רואה קישור.

Route: כלל בחירת דרך.

Established: חיבור TCP שנוצר.

Event ID: מזהה סוג אירוע.

RTT: זמן הלוך ושוב.

Listener: שירות שמאזין לפורט.

SRV: רשומת DNS לאיתור שירות.

Cache: מידע שמור זמנית.

שאלת סיום

איזו תוצאה של Test-NetConnection מוכיחה פתיחת TCP, ומה היא אינה מוכיחה לגבי היישום?

טעות נפוצה

הפלט של nltest מסתיים בשורה שהפקודה הצליחה, והטכנאי מסיק שה-Domain תקין, אף שהבדיקה עצמה נכשלה.
